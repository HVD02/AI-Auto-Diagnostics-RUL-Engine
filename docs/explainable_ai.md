# Explainable AI

## Method

SHAP `TreeExplainer` applied to the trained XGBoost fault-diagnosis model
(`backend/ml_core.py`, `_diag_explainer`). For a given prediction:

1. The explainer computes true SHAP values for every input feature against
   the predicted class.
2. The top 5 features by `|SHAP value|` are returned as the local
   explanation (`shap_explanation` field).
3. A one-sentence natural-language summary is generated by naming the top 2
   features directly from that list — e.g. *"CO2 and Consumption L/H were
   the strongest contributors to the current diagnosis."* This sentence is
   built from the model's actual output every time, never templated with
   invented sensor names.

## Global vs local

- **Local:** per-prediction SHAP values, shown on the Diagnostics and
  Explainable AI pages.
- **"Global" here** is represented as the full feature set the model was
  trained on (shown on the Explainable AI page) plus the aggregate model
  comparison table on Model Analytics — a true SHAP global summary plot
  (mean |SHAP| across the test set) can be added by extending
  `scripts/train_diagnosis.py` to persist `shap_values(X_test)` at training
  time; this build computes SHAP values live per-request for the local
  explanation, which is what the UI surfaces.

## Anomaly explanations (different method, disclosed)

The one-class anomaly models (Local Outlier Factor / Isolation Forest /
One-Class SVM) are not SHAP-tree-compatible, so their "explanation" is a
simple, disclosed alternative: per-sensor z-score magnitude over the
current window, ranked descending (`ml_core.run_anomaly` → `top_contributors`).
This is clearly a coarser signal than SHAP and is presented as such (z-score
contribution, not a SHAP value) — the UI never labels it "SHAP" to avoid
implying more rigor than it has.
